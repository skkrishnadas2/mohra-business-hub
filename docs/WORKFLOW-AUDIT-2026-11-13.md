# MOHRA — সম্পূর্ণ কাজের ধারা ও হিসাবের অডিট

তারিখ: ১৩ নভেম্বর ২০২৬। পাঁচটি পৃথক ইঞ্জিনিয়ারিং রিভিউ এবং সমন্বিত সংশোধন। এটি সোর্স-কোড, রেন্ডার করা UI এবং স্বয়ংক্রিয় পরীক্ষার অডিট; বাস্তব নবীন ব্যবহারকারীর পর্যবেক্ষণমূলক গবেষণা নয়।

## ব্যবহারকারীর কাজ অনুযায়ী যাচাই

| অংশ | যাচাই ও সংশোধন |
|---|---|
| হোম ও নেভিগেশন | মোবাইলে অ্যাকাউন্টস সরাসরি; শুরুর ভাউচার থাকলেও প্রথম সেটআপ নির্দেশনা; চার্টে শুরুর টাকা বা সেটিংস পরিবর্তনকে বিক্রি বলা হবে না; বাতিল মেমো বাদ; বাংলাদেশ সময় |
| শুরুর হিসাব | ক্যাশ/ব্যাংক/MFS/রিচার্জ → বর্তমান পণ্য → আগের পাওনা–দেনা → শিফট; আগে থেকে থাকা টাকা পুনরায় যোগ করার নির্দেশ নেই |
| POS | নিশ্চিত রসিদ আসার আগে কার্ট/স্ক্যান/পেমেন্ট সম্পাদনা বন্ধ; জমা কাজ থাকলে দ্বিতীয় বিক্রি বন্ধ; অকার্যকর অ্যাকাউন্ট ও ভুল ছাড়/স্প্লিট পেমেন্ট প্রত্যাখ্যান; খালি স্টকে পরের করণীয় |
| রিচার্জ | অপারেটর ও প্রতিটি সিমের হিসাবের ব্যালেন্স; নম্বরের মূল প্রিফিক্স অনুযায়ী সাজেশন; MNP-এর হাতে নির্বাচন অক্ষত; ভুল সিমে স্বয়ংক্রিয় বিকল্প নয়; পরের গ্রাহকে ক্যাশ ডিফল্ট |
| MFS | এজেন্ট/পার্সোনাল, প্রোভাইডার ও অ্যাকাউন্টের ব্যালেন্স স্পষ্ট; গ্রাহকের তথ্য সেভের পর সাফ; অকার্যকর/অনুমতিহীন অ্যাকাউন্টে নির্বাচন নয় |
| B2B | এজেন্ট ব্যালেন্স নেওয়া/দেওয়া; ক্যাশ/নির্দিষ্ট ব্যাংক নির্বাচন; দুই পাশের পূর্ব/পরের ব্যালেন্স; মূল টাকা লাভ নয়; আলাদা SR তালিকা বা পার্টি-খাতার বাকি নয় |
| নিজের অ্যাকাউন্ট | ফাঁকা ঘর দিয়ে ব্যালেন্স শূন্য হবে না; নতুন মোট ব্যালেন্সের স্পষ্ট ভাষা; অন্য ডিভাইসের নতুন লেনদেন পুরোনো সংশোধনে মুছবে না; স্টেটমেন্টে অনুমতিহীন অ্যাকাউন্টের তথ্য ফাঁস বন্ধ |
| আর্থিক পার্টি | কেনাবেচা ছাড়াও ধার/অগ্রিম/পাওনা/দেনা; পাওনা ও দেনা পৃথক; নিষিদ্ধ অ্যাকাউন্ট দিয়ে প্রিভিউ বা লেনদেন নয়; শুরুর হিসাব আর নতুন টাকা আলাদা |
| স্টক/ক্রয় | ফাঁকা আংশিক পেমেন্টে পুরো বিল বাকি নয়; পরের ক্রয়ে পুরোনো বাকি মোড নয়; ক্রয়/রিপেয়ারের ইতিহাস বা অবশিষ্ট স্টক মুছে পণ্য ডিলিট নয়; ক্রয়মূল্য বদলালে মূল্য-সমন্বয়ের জার্নাল |
| বারকোড/লেবেল | লোকাল প্রিন্টে সার্ভারের আর্থিক রসিদের অপেক্ষা নয়; মূল্য দেখানোর নির্বাচন; বাস্তব স্ক্যান/প্রিন্টের জন্য ডিভাইস পরীক্ষা |
| সার্ভিস | আগের গ্রাহকের খরচ পরের এন্ট্রিতে যাবে না; নির্বাচিত পেমেন্ট অনুযায়ী বাটনের ভাষা; সেভ চলাকালে ফর্ম লক |
| রিপেয়ার | ডেলিভারিতে অবশিষ্ট বিল স্পষ্টভাবে সংগ্রহ; সাধারণ স্ট্যাটাস ক্লিকে গোপনে ক্যাশ সংগ্রহ নয়; সম্পন্ন রিপেয়ার পুনরায় খুলে দ্বিতীয়বার বিল নয়; সিরিয়ালযুক্ত পণ্য অচিহ্নিত যন্ত্রাংশ হিসেবে খরচ নয় |
| শিফট | মোট ক্যাশ লেখা ডিফল্ট; নোট গণনা ঐচ্ছিক; ফাঁকা কাউন্ট বা ভগ্নাংশ নোটে শিফট শুরু/বন্ধ নয়; গরমিলে কারণ ও প্রয়োজনীয় অনুমোদন; অন্য কর্মীর শিফট বন্ধের সীমা |
| ফেরত/অনুমোদন | সেভের সময় মেমো/পরিমাণ বদলানো নয়; ক্যাশিয়ার শুধু নিজের অনুমোদনের অনুরোধ দেখবেন; পুরোনো ফেরতের রেকর্ড সংরক্ষিত |
| রিপোর্ট/মনিটর | বাংলা লেনদেনের ধরন; উল্টো তারিখে ব্যাখ্যা; SR-only নামকে আর্থিক পার্টির মোটে মেশানো নয়; বাতিল মেমো সক্রিয় বিক্রি হিসেবে নয়; বাতিলে স্পষ্ট নিশ্চিতকরণ |
| দোকান/টিম/লগইন | নেটওয়ার্ক ব্যর্থতাকে ভুল পাসওয়ার্ড বলা নয়; অ্যাকাউন্ট যুক্ত হওয়ার পর তালিকা লোড না হলে আবার অ্যাকাউন্ট তৈরির ভুল নির্দেশ নয়; সেভের সময় ফর্ম লক; সাইন-আউট ত্রুটি দৃশ্যমান |
| সেটিংস | সহজ বাংলা অনুমতি; বিরল নিয়ন্ত্রণ আলাদা করে ভাঁজ করা; প্রযোজ্য সীমা ও PIN ত্রুটি দেখানো; অনলাইন লগইন আর পুরোনো লোকাল PIN-এর পার্থক্য |
| ব্যাকআপ | অসম্পূর্ণ ফাইল আগে যাচাই; একাধিক ফাইল পড়ার রেসে পুরোনো ফাইল ফিরে আসবে না; পুনরুদ্ধারে ফর্ম লক; চালু ইতিহাস প্রতিস্থাপন সার্ভারে প্রত্যাখ্যান |

## হিসাব ও নিরাপত্তার গুরুত্বপূর্ণ নিয়ম

- প্রত্যেক আর্থিক কাজ অনুমোদিত ledger post এবং সার্ভারের রসিদে নিশ্চিত হয়। একই action ID-এর পুনরায় পাঠানো নতুন লেনদেন নয়।
- প্রকৃত ট্রান্সফার, ক্যাশ আদায় ও প্রোভাইডারে রিচার্জ আগে সম্পন্ন হয়; এই সফটওয়্যার তার দোকানের হিসাব রাখে। ব্যাংক/MFS-এর গোপন API বা লাইভ MNP lookup যোগ করা হয়নি।
- পুরোনো হিসাব বা জমা থাকা লেনদেন মুছে নতুন ডেমো ডেটা বসানো হয়নি। নতুন setBalance precondition ঐচ্ছিক; পুরোনো চার-আর্গুমেন্ট অনুরোধ সমর্থিত।
- স্টকের দাম পরিবর্তনের পুনর্মূল্যায়ন লাভ নয়; পরিমাণ কমার বিদ্যমান স্টক-ক্ষতি আলাদা জার্নালে থাকে।
- ঋণ/ধার/অগ্রিমের মূল টাকা লাভ নয়। MFS B2B মূল টাকা লাভ নয়। রিচার্জ ক্রয়ের অতিরিক্ত ব্যালেন্স পৃথক কমিশন।
- মাইনাস অঙ্ক পেস্ট করলে তা ধনাত্মক টাকায় বদলে যাবে না; যাচাই করে প্রত্যাখ্যান করা যাবে।

## যা বাস্তবে আরও যাচাই করতে হবে

1. দোকানের নির্দিষ্ট মোবাইল ক্যামেরায় বারকোড পড়া, USB/Bluetooth স্ক্যানারের আচরণ এবং নির্দিষ্ট থার্মাল প্রিন্টারের মাপ/কাটার। অ্যাপে ডিভাইস পরীক্ষার ব্যবস্থা আছে; এই অডিটে বাস্তব হার্ডওয়্যার চালানো হয়নি।
2. মালিক ও ক্যাশিয়ারকে দিয়ে বাস্তব ছোট একটি কাজের সেশন চালালে বোঝা যাবে ভাষা/ধাপ তাদের কাছে কতটা সহজ। স্বয়ংক্রিয় পরীক্ষা দিয়ে সব নবীন ব্যবহারকারীর বোঝাপড়ার নিশ্চয়তা দেওয়া যায় না।
3. পাসওয়ার্ড রিসেটের ফর্ম ও লিংকের হ্যান্ডলিং পরীক্ষিত; ইমেইল ইনবক্সে পৌঁছানোর SMTP/ডেলিভারি এই অডিটে নতুন করে সম্পন্ন বা যাচাই করা হয়নি। আগের স্থগিত মেইল সেটআপ আলাদা কাজ।
4. আসল দোকানের হিসাবে পরীক্ষামূলক বিক্রি/ধার/স্টক/ট্রান্সফার যোগ করা হয়নি। আর্থিক কেসগুলো আলাদা টেস্ট স্টোরে চালানো হয়েছে।

## এই সংস্করণের যাচাই

- TypeScript পরীক্ষা পাস।
- `npm run test -- --maxWorkers=2`: ৪০টি টেস্ট ফাইলের ৩০৭টি কেস পাস। প্রথম সীমাহীন সমান্তরাল রান পরিবেশের চাপে একটি DOM পরীক্ষায় ৫ সেকেন্ডের timeout হয়েছিল; সীমিত সমান্তরালতায় পুরো suite পাস করেছে।
- সার্ভার contract/PWA পরীক্ষা এবং production build প্রকাশের আগে আলাদাভাবে চালানো হয়।
- আগের হিসাব সংরক্ষিত রেখে একই GitHub repository, Supabase business-api ও Cloudflare Worker-এ প্রকাশ করা হয়; কোনো schema migration নেই।

চূড়ান্ত যাচাই: ৩০৭টি UI/domain + ১৫টি server/PWA = ৩২২টি স্বয়ংক্রিয় পরীক্ষা পাস; production build সফল।
